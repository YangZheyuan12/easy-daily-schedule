### 实现期的一处架构调整（已告知用户）
**移除 MUI v5，改为 Tailwind + 手写移动端组件**。理由：
① MUI + Tailwind 需处理 preflight 冲突；② 包体省掉约 300KB；

其余架构决策（Zustand / Dexie / 邻接表 / 分层红线 / 软删只改 deletedAt）全部照架构文档执行。
最终产物 gzip 102KB（JS 102KB + CSS 4.4KB）。

## 同日第三轮：增量需求「日历页」（已完成）

用户要求：有日历的页面，当日任务和完成情况与日历对应日期挂钩。

### 用户拍板的三项设计决策
1. 入口：底部 Tab 第三项「📊 统计」→「📅 日历」，路由 `/stats` → `/calendar`（不新增第 5 个 Tab）
2. 格子标记：每格四个小色点对应四大板块，实心=当天该板块有顶层记录，灰点=无记录；今天蓝色描边高亮
3. 点击行为：留在日历页显示当天摘要卡（四板块进度条 + 任务 + 总评 + 整体完成率），
   右上角「去补记 ›」才跳 `/today` 并切换 `useDayStore.date`

### 关键实现
- **未改表结构**：`date` 已是 Dexie 索引，`listByDateRange` 直接 `where('date').between(start,end,true,true)`，零数据迁移
- **整月三次查询**（items/tasks/reviews），不是 30 次单日查询
- `services/calendarService.ts` 为月历网格全部 42 格产出摘要，四板块复用 `progressService.computeAllSections()`，
  保证与首页环形图口径绝对一致（有专门的等价性 Assert 测试锁住）
- 新增文件：`services/calendarService.ts`、`store/useCalendarStore.ts`、
  `components/calendar/{DayCell,MonthGrid,DaySummaryCard}.tsx`、`pages/CalendarPage.tsx`
- 删除 `pages/StatsPage.tsx`

### QA（严过关）独立审查发现 3 个真实缺陷，全部修复并补测试锁住
1. **BUG-1 补位格摘要说谎**：`buildMonthSummaries` 对非当月补位格返回空摘要，但 `DayCell` 不区分
   inMonth、灰格可点击 → 用户点 9/30 会看到「这一天还没有任何记录」，而当天明明有数据。
   修复：分组范围改为全部 42 格；「本月不被上下月污染」由按日期精确分组保证（两件事正交）
2. **BUG-2 并发竞态**：连点两下「下一月」，迟到的旧响应覆盖新结果 → 表头是 12 月、格子里是 11 月数据，
   且 selectedDate 被甩到摘要表覆盖不到的 key 上，摘要卡再次谎报。
   修复：`requestSeq` token 丢弃过期结果（含 catch 分支）+ `shiftMonth` await 后二次校验 monthKey
3. **BUG-3 口径防御**：`buildDaySummary` 不校验入参日期，将来被周视图等调用会造成口径分叉。
   修复：函数内按 date 自行过滤并校验 review.date

### 🔴 重要环境陷阱（不是项目缺陷）
在本机一次性 `vitest run` 跑全部文件时，会偶发抛 `EPERM ... %TEMP%` 并**静默丢掉某一个测试文件**
—— 用例总数变少，但**退出码仍为 0 且整体显示绿色**。这是 WorkBuddy 沙箱 fs 代理层的限制，
尝试重定向 TEMP/TMP 到项目内目录**无效**（我尝试过并已回滚该改动）。
**验收必须逐文件跑并核对总数，当前基线 161，不能只看「显绿」。**
