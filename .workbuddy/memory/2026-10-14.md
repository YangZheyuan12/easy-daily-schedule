## H5 → 手机 App 迁移评估（只出文档，未改代码）
用户问「这个项目是网站还是 App、做成手机 App 改动大吗」，产出
**`docs/MOBILE-APP-MIGRATION.md`**（新增）。

结论要点（供以后直接引用，不要重算）：
- 现状是 **移动端优先 H5 网页**（Vite+React+HashRouter+IndexedDB），**不是 App**。
  无 `public/`、无 manifest、无 service worker、无原生工程目录。
- 规模快照（采集 2026-10-14）：src 131 文件；生产代码 ~8.8k 行 TS/TSX + 575 行 CSS；
  测试 ~6.9k 行；`dist/` 396 KB（JS 369 KB + CSS 28 KB）。
- 分层行数（不含测试）：domain 495 / services 2098 / store 985 / utils 343 / hooks 216 /
  components 2754 / pages 1125 / theme 158 / router 33 / repositories 618。
  → 零浏览器依赖层（domain+services+utils）= **2936 行**（若含 store 则 3921 行，占 44%）。
- **全库仅 9 处触碰浏览器 API**（排除 repositories 与测试）：
  main.tsx（createRoot）、repositories/*（Dexie）、LocalSettingsRepository（localStorage）、
  AppRouter（HashRouter）、store/bootstrap.ts（visibilitychange/pagehide）、
  Sheet.tsx（document.body.style.overflow）、TimeRuler.tsx（window pointer 事件）、
  useKeyboardAvoid.ts（visualViewport）、useApplyTheme.ts + index.html（documentElement）。
- 四条路线：A PWA（1–2 天）/ **B Capacitor 套壳（推荐，1–2 周，业务代码零改动）** /
  C 微信小程序走 Taro（3–5 周，存储层要整套重写 ~400–600 行，通知能力会退化）/
  D React Native 重写（不推荐）。
- 关键坑已写进文档：iOS 上 PWA 无本地通知；iOS 打包需 macOS/Xcode；
  国内安卓上架需 App 备案 + 软著；小程序订阅消息需服务端。

**本轮踩到 / 查证到的三件事（重要，别重复踩）**：
1. `ios: { scheme: 'https' }` 是我先写错的 —— Capacitor 8 的正确写法是顶层
   `server.iosScheme`，而且 **WKWebView 不允许 http/https**。查证后结论是
   **根本不该改**：「改 scheme」是从 Cordova 迁移的处方（origin 变了旧数据读不到），
   本项目无历史 origin。真正风险是 iOS 会回收 WebView 数据 → 导出导入优先级最高。
2. tsc 抓到两处真实 API 误用（`persistence.flush('native-pause')` 不在 `FlushReason` 里、
   `Keyboard.setAccessoryBarVisible` 参数是 `isVisible` 不是 `visible`）
   —— **测试与 vite build 都发现不了**，再次印证「tsc 必须单跑」。
3. 沙箱里 `npm run verify` 因 vitest 写 `%TEMP%` 的 EPERM 使 vitest 退出码非 0，
   **导致链上最后的 `vite build` 根本没跑**（88x 用例全绿也会漏）。
   且整包只跑了 38 个文件，`test:strict` 是 39 个 → 又印证「显绿 ≠ 跑全」。
   本轮补跑了 `npx vite build`（377 KB JS + 28.7 KB CSS）与 `npm run test:strict`
   （**39 文件 / 940 用例 / 失败 0**）。

## iOS job 反复失败的最终处置（7daa9a7）
- 现象：`xcodebuild -sdk iphoneos ... CODE_SIGNING_ALLOWED=NO` **报 BUILD SUCCEEDED 却产不出 .app**
  （`find` 找不到任何 .app，Zip 步骤失败）。
- 🔴 **GitHub 的 job 日志需要仓库管理员权限**（匿名 REST 返回 403
  "Must have admin rights to Repository."），`gh` 也没装 → **远程看不到任何输出**。
  推论：CI 里凡是「可能出错且靠猜」的步骤，都要自己打诊断输出；但**看不到日志时诊断也没用**，
  所以更该做的是**换一条确定不会踩坑的命令**，而不是继续猜。
- 处置：iOS job 改编**模拟器版**（`-sdk iphonesimulator -destination 'generic/platform=iOS Simulator'`），
  模拟器构建**不需要签名**，不会再因为签名被禁用而拿不到产物。产物改名 `ios-simulator-app`。
- 结论已写进 README + 迁移文档：**iOS 必须有 Mac，没有第三条路**（Apple 不允许未签名 App

## R-042：时间轴归类时间段同步到今日页（已实现）
需求原话：「时间轴里填的、已经选了板块的条目（9–10 点开组会、板块=工作），
也应该出现在首页今日的分类列表里。」

**先问后做**（用户三项均选推荐项）：
① 只做时间轴，**每日任务不动**（`Task` 根本没有 `sectionId`，加字段要升 v4 schema + 迁移）；
② 计入板块完成率；③ 排在该板块现有条目之后。

实现（只读投影，不复制数据）：
- `DiaryEntry.kind` 增 `'timeSlot'`，新增 `timeSlot?: TimeSlot` 字段
- `buildDiaryList(items, inspirations, timeSlots)` 加**必填**第三参；板块内先铺条目树、
  再 `sortSlots` 追加归类时间段（startMin → order → createdAt），编号接着走
- `DiaryList` 读 `useTimeSlotStore.slots`；组头计数改为 `kind==='item'||'timeSlot'`；
  时间段行 = 编号 + Tick + `09:00` 时间标记 + 标题，勾选 `toggleDone(slot.id)`，点行跳 `/timeline`
- 13 处旧测试调用点补齐第三参（`buildDiaryList(x, [], [])`）

**顺带修掉一个既有口径不一致**：`calendarService.buildDaySummary` 早就把归类时间段并进
`DaySummary.sections`，但今日页组头原先只数 items → 同一天两处显示不同数字。现已对齐。
**刻意不改 `SectionPage`**（板块详情页仍只数 items，它管的是条目树）。

验证：`tsc --noEmit` 通过；**负向验证做过**（把投影 filter 改成 `false` → 5 个新用例真的红，
不是空跑）；`test:strict` **947 用例 / 39 文件全绿**（改动前 940，+7）；
`check:layers` 通过（131 文件）；`vite build` 378 KB JS + 28.7 KB CSS。

## R-043：任务页五分组 + 同步到今日（已实现）
需求原话：任务页加五个分组（四大 + 其他）、加「同步」按钮、弹框确认后把四大分组内容
加到今日页条目后面，**「其他」不用管**。

与 R-042 的关键差别：**这里是一次性复制，不是只读投影**（用户要的是「按钮 + 确认」这个动作）。
去重靠 `Item.sourceTaskId` —— `planTaskSync` 排掉今日页已存在同来源条目的任务，
所以重复点按钮不会堆两份。

- `Task.sectionId: TaskSectionKey`（四大 + `'other'`）；**老数据 / 新任务都归一化为 `'other'`**，
  **绝不默认某个板块** —— 否则一次同步会凭空造出一批用户没打算同步的条目
- **零 Dexie 变更**：`sectionId` / `sourceTaskId` 都不是索引 → `DB_VERSION` 仍为 3，无需迁移
  （这是本次最大的省事点：一开始以为要升 v4）
- `services/taskSyncService.ts`：`planTaskSync`（挑草稿，纯函数）+ `createSyncedItems`
  （复用 `createSiblingAfter` 落地，连「order 精度耗尽整层重排」一起继承）
- **move 改成组内换位**：跨组换位会让一行任务跳到另一个分组，看起来像消失又出现在别处
- UI：任务页按非空分组分段（空组不渲染 —— 它没有入口功能，添加走底部按钮）；
  行首 10px 分组色点 → `SectionPickerSheet`；新增 `ConfirmSheet`（不用 `window.confirm`，
  它在纸感主题上像报错弹窗）；Icon 新增 `sync`
- 新任务默认落在「其他」；继承昨日时**保留原分组**（昨天归工作、今天还是工作）

验证：tsc 通过；`check:layers` 通过（135 文件）；vite build 383 KB JS + 28.9 KB CSS；
**两处负向验证都做过**（去掉「其他」过滤 + 幂等检查 → 2 个用例红；
把 move 改回全局换位 → 2 个用例红）；`test:strict` **962 用例 / 40 文件全绿**（+15）。
