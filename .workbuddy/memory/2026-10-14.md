## H5 → 手机 App 迁移评估（只出文档，未改代码）
用户问「这个项目是网站还是 App、做成手机 App 改动大吗」，产出
**`docs/MOBILE-APP-MIGRATION.md`**（新增）。

结论要点（供以后直接引用，不要重算）：
- 现状是 **移动端优先 H5 网页**（Vite+React+HashRouter+IndexedDB），**不是 App**。
  无 `public/`、无 manifest、无 service worker、无原生工程目录。
- 规模快照（采集 2026-10-14）：src 131 文件；生产代码 ~8.8k 行 TS/TSX + 575 行 CSS；
  测试 ~6.9k 行；`dist/` 396 KB（JS 369 KB + CSS 28 KB）。
- 分层行数（不含测试）：domain 495 / services 2098 / store 985 / utils 343 / hooks 216 /
  components 2754 / pages 1125 / theme 158 / router 33 / repositories 618。
  → 零浏览器依赖层（domain+services+utils）= **2936 行**（若含 store 则 3921 行，占 44%）。
- **全库仅 9 处触碰浏览器 API**（排除 repositories 与测试）：
  main.tsx（createRoot）、repositories/*（Dexie）、LocalSettingsRepository（localStorage）、
  AppRouter（HashRouter）、store/bootstrap.ts（visibilitychange/pagehide）、
  Sheet.tsx（document.body.style.overflow）、TimeRuler.tsx（window pointer 事件）、
  useKeyboardAvoid.ts（visualViewport）、useApplyTheme.ts + index.html（documentElement）。
- 四条路线：A PWA（1–2 天）/ **B Capacitor 套壳（推荐，1–2 周，业务代码零改动）** /
  C 微信小程序走 Taro（3–5 周，存储层要整套重写 ~400–600 行，通知能力会退化）/
  D React Native 重写（不推荐）。
- 关键坑已写进文档：iOS 上 PWA 无本地通知；iOS 打包需 macOS/Xcode；
  国内安卓上架需 App 备案 + 软著；小程序订阅消息需服务端。

**本轮踩到 / 查证到的三件事（重要，别重复踩）**：
1. `ios: { scheme: 'https' }` 是我先写错的 —— Capacitor 8 的正确写法是顶层
   `server.iosScheme`，而且 **WKWebView 不允许 http/https**。查证后结论是
   **根本不该改**：「改 scheme」是从 Cordova 迁移的处方（origin 变了旧数据读不到），
   本项目无历史 origin。真正风险是 iOS 会回收 WebView 数据 → 导出导入优先级最高。
2. tsc 抓到两处真实 API 误用（`persistence.flush('native-pause')` 不在 `FlushReason` 里、
   `Keyboard.setAccessoryBarVisible` 参数是 `isVisible` 不是 `visible`）
   —— **测试与 vite build 都发现不了**，再次印证「tsc 必须单跑」。
3. 沙箱里 `npm run verify` 因 vitest 写 `%TEMP%` 的 EPERM 使 vitest 退出码非 0，
   **导致链上最后的 `vite build` 根本没跑**（88x 用例全绿也会漏）。
   且整包只跑了 38 个文件，`test:strict` 是 39 个 → 又印证「显绿 ≠ 跑全」。
   本轮补跑了 `npx vite build`（377 KB JS + 28.7 KB CSS）与 `npm run test:strict`
   （**39 文件 / 940 用例 / 失败 0**）。
