结论要点（供以后直接引用，不要重算）：
- 现状是 **移动端优先 H5 网页**（Vite+React+HashRouter+IndexedDB），**不是 App**。
  无 `public/`、无 manifest、无 service worker、无原生工程目录。
- 规模快照（采集 2026-10-14）：src 131 文件；生产代码 ~8.8k 行 TS/TSX + 575 行 CSS；
  测试 ~6.9k 行；`dist/` 396 KB（JS 369 KB + CSS 28 KB）。
- 分层行数（不含测试）：domain 495 / services 2098 / store 985 / utils 343 / hooks 216 /
  components 2754 / pages 1125 / theme 158 / router 33 / repositories 618。
  → 零浏览器依赖层（domain+services+utils）= **2936 行**（若含 store 则 3921 行，占 44%）。
- **全库仅 9 处触碰浏览器 API**（排除 repositories 与测试）：
  main.tsx（createRoot）、repositories/*（Dexie）、LocalSettingsRepository（localStorage）、
  AppRouter（HashRouter）、store/bootstrap.ts（visibilitychange/pagehide）、
  Sheet.tsx（document.body.style.overflow）、TimeRuler.tsx（window pointer 事件）、
  useKeyboardAvoid.ts（visualViewport）、useApplyTheme.ts + index.html（documentElement）。
- 四条路线：A PWA（1–2 天）/ **B Capacitor 套壳（推荐，1–2 周，业务代码零改动）** /
  C 微信小程序走 Taro（3–5 周，存储层要整套重写 ~400–600 行，通知能力会退化）/
  D React Native 重写（不推荐）。
- 关键坑已写进文档：iOS 上 PWA 无本地通知；iOS 打包需 macOS/Xcode；
  国内安卓上架需 App 备案 + 软著；小程序订阅消息需服务端。

## R-043 改版：任务页退回平铺，分组退化为行属性（同日，用户纠正指令）

- `TaskRow`：行首标记 —— 四大板块=实心色点，「其他」=**空心圈**（形态区分"未分组"）；
  **聚焦（正在填写）时才展开组名**，静态排版只留点（写的时候必须能看见自己选的是什么）
- `useTaskStore.move`：**退回全局换位**，边界=整条列表首尾。
  平铺列表下若限制组内换位，按「下移」会毫无反应而下面明明还有一行 → 像按钮坏了
- 测试：`useTaskStore.move — 分组不参与换位判断`（4 用例，含跨组互换、跨边界下移、
  换位后分组保留、末行空操作）。**负向验证做过**：临时插入「跨组换位变空操作」

## R-044：周视图（课程表 + 田字格）+ 本月时长条

③ 周表纵向**按当周数据自动收窄**；④ 田字格内**按天分组列事项**。

- 时长条复用月历那次取数（`fetchMonth` 已拉 timeSlots），**不额外查库**；
  但必须按 `date.startsWith(monthKey)` 过滤，否则邻月补位日会算进来
- 田字格只取**顶层条目 + 归类时间段**（与今日页完成率口径一致）

## 导入课程表功能：仅评估难度（未实现）
用户问「能否设计导入课程表」，要求只回难度不实现。结论：
- **推荐路线 = 手动录入「每周模板」+ 只读投影**（新增 `CourseSlot{weekday,startMin,endMin,content,sectionId}` 实体，
  时间轴课程表在 `buildWeekTimetable` 里把模板按星期几投影成伪槽、与真实 `TimeSlot` 同帧并排 lane）。
  **难度：低~中（偏低）**，约几天量；完全符合本项目「只读派生、不复制数据」哲学，且不碰写入路径。
- 文件导入（CSV/ICS，如学校系统导出）：需解析 + 字段映射 UI + 校验 → **中**。
- 学校系统直连 / 截图 OCR → **高**，且不符本地优先无后端定位。
- 主要风险点：① 与现有 `slot.date===dateKey` 过滤 + 重叠并排逻辑要融合，不能破 lane 计算；
  ② 调课/节假日例外用「真实 TimeSlot 覆盖模板」解决；③ 项目**尚无导出/导入基建**（iOS 回收数据的最高优先风险），
  文件导入会连带要求先把这套基建补上。
- 决策建议：**先做手动模板（低难度、架构友好），文件导入后置**，别一上来就做 OCR/直连。
