
## 修复「只能取消长期任务、不能添加」的 bug（2026-10-27 深夜）
- 现象：任务页点定住图钉，老任务只弹「取消长期任务」，无法「设为长期任务」。
- 根因：`IndexedDbTaskRepository.normalizeTask` 只归一化了 `sectionId`/`kind`/`description`，
  **漏了 `pinFrom`/`pinUntil`**。老数据（定住功能上线前的任务）缺这两个字段，Dexie 读出是
  `undefined`，而业务层用 `pinFrom !== null` 判断「是否已定住」——`undefined !== null` 恒为 true，
  于是所有老任务被误判成「已定住」：图钉恒实心、`pin()` 里 `if (pinFrom !== null) return` 直接
  拦截，导致「只能取消、不能添加」。
- 修复：`normalizeTask` 补 `pinFrom: task.pinFrom ?? null`、`pinUntil: task.pinUntil ?? null`，
  与 `sectionId`/`kind`/`description` 同一套「老数据归一化」约定。仓储是唯一读写出口，
  归一化在此一处即覆盖 listByDate / listByDateRange / listAll 全部读路径。
- 新增 `src/repositories/__tests__/IndexedDbTaskRepository.test.ts`：① 老数据缺 pinFrom/pinUntil
  读出来归一化为 null（用 `as unknown as Task` 绕过类型约束，模拟真实老数据缺 key 的运行时形态）；
  ② 已有定住字段原样保留。回归锁定。
- 验收：typecheck 0 错；check:layers 277 文件；build 成功；全量测试 **90 文件 / 1396 用例全绿**。
  仍未提交（与之前几轮改动合并待提交）。

## 修复「取消长期任务后仍显示定住态」的 bug（2026-10-27 深夜二）
- 现象：点「取消长期任务」确认后，图钉仍是实心竖直（定住态），看起来像没生效。
- 根因：UI 判断「是否定住」一律用 `pinFrom !== null`，但 `unpin` 的语义是「延迟取消」——
  只设 `pinUntil = 取消日+1`，`pinFrom` 保持非空。于是取消后 pinFrom 仍非空，图钉纹丝不动。
  「投影是否生效」和「视觉定住态」被混成了一个概念。
- 修复：新增纯函数 `isActivelyPinned(task) = pinFrom !== null && pinUntil === null`（区分
  「活跃定住中」与「已取消」）。UI 的图钉图标 / 点击文案 / ConfirmSheet 判断全部从
  `pinFrom !== null` 改用 `isActivelyPinned`：
  - TaskRow：`pinned = isActivelyPinned(task)` 驱动实心/空心、竖直/斜向、title/aria；
  - TasksPage ConfirmSheet：title/message/confirmText/onConfirm 分支都用 isActivelyPinned。
  - 🔴 「投影是否生效」仍用 `isPinnedOn(task, date)`（延迟取消，取消当天仍投影）——
    两个概念必须分开，不能互相替代。
- 连锁修复：`pin()` 支持「取消后再设回」——已取消（pinFrom 非空 && pinUntil 非空）的任务
  再点设为长期任务时，清掉 pinUntil 恢复活跃定住（原来 `if (pinFrom !== null) return` 会
  卡死这个路径）；全新定住才写 pinFrom=date。`toggleDone` 的 `pinFrom !== null` 判断保持
  不变（它判的是「done 是否按天独立」，只要定住过就成立）。
- 新增 `src/services/__tests__/pinProjectionService.test.ts`：isActivelyPinned 三态、
  isPinnedOn 延迟取消（当天仍投影/次日停）、isPinProjection 本体 vs 投影。
- 验收：typecheck 0 错；check:layers 278 文件；build 成功；全量测试 **91 文件 / 1403 用例全绿**。
  仍未提交（与之前几轮改动合并待提交）。

## 今日页同步条目不再显示删除线（2026-10-27）
- 现象：任务页「同步到今日」勾选任务后，出现在今日页的条目若是来源任务已完成，会带删除线 + 淡化字重。
- 根因：今日页 `DiaryList` 的 `EditableTitle` 按 `item.done` 画删除线；而同步会把来源任务的
  `done` 原样复制成条目的 `done`（taskSyncService 设计如此，且被单测锁死），今日页又**没有**
  完成开关可取消 → 来源任务一勾完，今日页这条就永久置灰、无处可取消。
- 修复（纯展示层，不动数据）：`DiaryRow` 计算 `isSynced = sourceTaskId!==null || sourceSlotId!==null`，
  `displayDone = done && !isSynced`，同步来源的条目一律按「未完」展示（不画删除线、字重不淡化）。
  底层 `done` 数据保留，日历完成度等统计仍计入来源完成情况。
- 仅改 `src/components/diary/DiaryList.tsx`（DiaryRow + EditableTitle 加 `done` 入参）。
  验收：tsc 0 错；相关测试 42 全绿。尚未提交。

- 用户诉求：不想被固定在 OpenAI/Anthropic/Gemini 三个厂商；想直接填自己的 Base URL
  （如 DeepSeek 的 https://api.deepseek.com/v1），且填完 URL + Key 后点一下就能拉到模型名，
  不用手填模型名。
- 实现：
  - `domain/types.ts`：`AiProvider` 增加 `'custom'`；`AiProviderConfig` 注释补 custom 说明。
  - `domain/ports.ts`：`AiGateway` 增加 `listModels(config, apiKey): Promise<string[]>`。
  - `platform/ai/index.ts`：`createAiGateway('custom')` → OpenAI 兼容网关（DeepSeek/GLM/通义/Kimi 都兼容）；
    `AI_PROVIDER_DEFAULTS` 增 `custom`（baseUrl/model 空，label「自定义（任意 OpenAI 兼容端点）」）。
  - 三个网关各自实现 `listModels`：OpenAI 兼容 `GET /models`（Bearer）；Gemini `GET /models?key=`；
    Anthropic `GET /models`（x-api-key + anthropic-version）。鉴权失败/无列表能力抛 DomainError。
  - `services/aiService.listModels(config, apiKey?)`：缺 URL 抛错；密钥优先用传入值，否则回退
    已存密钥（已保存过密钥时无需重复输入）。

  - UI（`pages/MePage.tsx` 的 `AiSettingsCard`）：厂商下拉自动多出「自定义」；Base URL 输入框
    提示 `https://your-endpoint/v1`；模型名下方加「获取模型」按钮（拿当前 URL + Key 拉列表），
    拉到后渲染下拉供选择；切换厂商 / 改 URL 时 `clearModels` 清掉旧列表；Key 已保存但框为空时
    仍可获取（service 回退读存储密钥）。
