## 顶部日期可跳日历选日子（用户反馈「点击顶部的时间无法跳转」）

问题根因：`DateNavigator` 早就留了 `onDateClick`，但**今日页压根没传**（占位点只在时间轴页接了），
任务页更是只把日期写死在 `PageHeader` 的副标题里，没有任何入口。

改法（三页统一走「选日子」语义）：

- **日历页双语义**，由 `location.state.pickDateFrom` 区分，别再给日历加第二个组件：
  - 回看模式（底部 Tab 进来）：点一格只更新摘要卡，不跳页（原行为，保留）。
  - 选日子模式（从日期进来）：点一格 → `setDate` + `navigate(pickFrom, { replace: true })` 回来路，
    顶部补返回按钮、副标题改成「点一格即切换到那一天，并回到上一页」。
  - 判断依据是**「用户是不是从某个日期点进来的」**，不是屏幕本身 —— 同一个组件两种语义，
    比新开一个 `DatePickerSheet` 更省，也避免日历逻辑被复制两份。
- 入口三处：今日页 `onDateClick`、任务页副标题里的日期改成 `<button aria-label="选择日期">`、
  时间轴页原 `onDateClick` 升级为带 `pickDateFrom`。
- `PageHeader.subtitle` 类型 `string` → `ReactNode`：任务页要「日期可点 + 完成度不可点」，
  不能整条副标题都做成按钮（点「完成 2/6」跳日历会让人费解）。
  点区用 `-my-2 py-2` 撑到 32px，**不改变视觉行高**。
- 顺带修「今天」措辞（日期能翻之后这就成了谎话，项目既有原则是「不说谎」）：
  任务页空状态 `今天还没有任务` → 非当天时 `10月15日 还没有任务`；
  自我状态条 `点这里记录今天的状态` → 非当天时 `点这里记录这一天`。

## 动效体系（用户反馈「UI 比较死板，设计一些有质感的方案」）

改前只有 2 个 keyframe（抽屉进出场），其余全是硬切。

### 动效 token（写进 `src/styles/index.css`，**不随三主题变**）
`--m-dur-1/2/3/4` = 120/200/280/340ms · `--m-ease-out`(0.22,1,0.36,1) · `--m-ease-in-out`
· `--m-ease-spring`(0.34,1.5,0.64,1) · `--m-ease-sheet`。
**决策：动效全局一套，不进主题系统。** 三主题换的是形态/配色/信息密度，不是「另一个 App 的手感」；
把动效也主题化会让「纸感」和「夜航」的手感分裂，且 token 面积翻三倍。

### 四条动效规则（后续新增动效必须遵守）
1. **>30px 的面只用 ease-out、不回弹**；≤20px 的微元素（勾选框、心/星、日期数字）才允许过冲。
2. **循环动效只允许播一次**（到点提醒横幅 = 2 次呼吸后停），持续闪烁会让人焦虑。
3. **方向即语义**：下一天从右进 / 上一天从左进 / Tab 指示器横滑 / 抽屉从底升。
4. 时长分四层，**>340ms 就显迟钝**（所以面板 340ms 封顶）。

### 核心陷阱：CSS animation 首次挂载也会播
最典型写法 `className={done ? 'm-tick' : ''}` 会让「打开页面时所有已完成条目集体弹一下」。
解法是新建 `src/hooks/useRecentlyChanged.ts`：只在**挂载之后**的后续变化返回 true
（`Object.is` 比较 + `holdMs` 后复位），StrictMode 双挂载安全。勾选/心星/评分/日历选中圆全部走它。
**已实测**：重载后已完成勾选框 `animationName: none`，同时列表行仍播 `m-rise`。

### 落点（新增 12 个 keyframe / 14 个 utility）
勾选 `m-tick-pop` + `m-check-draw`（盒子弹 0.76→1.14→1，同时 svg path 用 `stroke-dasharray:22`
70ms 后画出对勾）；划线 `m-strike`（`background-size` 0→100% 真「画出来」）
/ `m-strike-ink`（`text-decoration-color` 透明→currentColor 淡入，用于塞不进 span 的 `<input>`）；
列表 `m-rise` + `staggerDelay()`（24ms/行，第 6 行封顶）；Tab 指示器独立浮层
（`useLayoutEffect` 测 offsetLeft/offsetWidth + `ResizeObserver` + `transition-[transform,width,opacity]`）；
抽屉三态 `phase: idle|in|out`（退场 200ms 后才卸载）+ pointer 拖拽跟手（距离 28% 或速度 0.55px/ms 判定关闭）；
自我状态卡 `grid-template-rows: 0fr→1fr` 高度过渡（折叠时对内容设 `inert`）；
`tap-expand` 伪元素扩命中区（16px 视觉勾选框 → 32px 命中区，**行高不变**）；
`.press`（`:active scale(0.96)`）；`prefers-reduced-motion` 全局退化到 **1ms 而非 0**
（0s 不触发 animationend，会让「动画结束再卸载」的抽屉卡住不关）。

### 本轮最有价值的排错：改 `animation-name` 会让动画从头重播
`MonthGrid`/`DateNavigator` 原本用 `useRef` 在渲染期算 direction。实测抓到
「换月 90ms => `anim:"m-fade"`」—— 取数后 store 又 set 一次（loading→false）时 monthKey
已等于 ref → direction 变 0 → class 从 `m-slide-right` 悄悄变回 `m-fade`，动画重播成淡入。
改用 **React 渲染期派生 state**（`if (prev !== value) { setPrev(value); setDirection(...) }`）锁住方向后，
复验 `换月 90ms => m-slide-right, tx:1.35`，三帧采样稳定。

`useRecentlyChanged`(4) / `Tick`(4) / `BottomTabBar`(4，需 mock `ResizeObserver`) / `staggerDelay`(3)。

验收：`check:layers` ✓(112 源文件) / `typecheck` ✓ / `test:strict` ✓「343 用例 27 文件 失败 0」

### 一、先立「字号刻度」，再谈放大
散落各处的 `text-[Npx]` 有 **98 处 / 23 个文件 / 10 个不同数值**。直接逐个改是改不动的，
下一次「再大一点」还要再来一遍，于是先建刻度：

- `index.css` 的 `:root { --fs-* }` 定义九档，`tailwind.config.ts` 的 `fontSize` 映射成语义类名：
  `label 11 / micro 12 / caption 13 / meta 14 / body 15 / lead 16 / heading 18 / title 24 / display 32`。
- 写了个 codemod（`.workbuddy/tmp/fontscale.js`）把 98 处机械替换掉，映射**刻意多对一**
  （旧 16 与 17 都归 `heading` —— 本来就是同一角色，只是历史遗留差异）。
- 两个必须记住的实现细节：
  ① **Tailwind 的 fontSize 值要写纯字符串**（`'var(--fs-body)'`，不带 lineHeight 对象），
     否则会盖掉组件里已有的 `leading-*`；写对象就等于把行距一起劫持了。
  ② 名字**不能带像素值**（`--fs-15`）—— 档位会随整体缩放漂移，一年后名字必然说谎。
- 与颜色同一套思路：**语义类名永不变，值换成变量**。这也是「整站再调一次」的成本从 23 个文件
  降到 9 行的关键。

### 二、今日页层级（用户点名）
原来组头 13px **比它下面的添加项 14px 还小**，层级是反的。改成：
**组头 18px SemiBold（色点 6→8px）＞ 顶层条目 16px ＞ 内联添加 15px（弱化色）**。
实测 computed style：18/600、16、15 —— 拉开 3px + 一个字重档，扫一眼就知道一段属于谁。

### 四、时间选择器：原生 `input[type=time]` → 可滑动刻度尺
新建 `src/components/ui/TimeRuler.tsx`：小时 24 格 + 分钟 12 格（步长 5）两层横向刻度条。
- 放弃原生的理由：桌面端弹系统面板（全应用唯一不跟主题的地方）、手机端盖住半屏，
  而排时间段最需要的恰是「看到前后几小时的上下文」。
- 交互：拖动 / 点击 / 触摸原生横滑 / **Shift+滚轮或横向滚轮**（普通纵向滚轮**不劫持**，
  否则鼠标停在尺子上抽屉就滚不动了 —— 这比少一种浏览方式严重得多）。
- **踩到的坑**：一开始用 `setPointerCapture`，结果 click 被重定向到捕获元素、刻度永远点不到。
  改成 window 监听 pointermove/pointerup。Sheet 顶栏拖拽注释里其实早写过同一件事，没读到。
- 另一个坑：滚动复位的依赖**只能是 fieldKey，不能是 selected** —— 拖动时值也在变，
  依赖 selected 就会和用户的手指抢滚动位置。
- hover 要的「放大、加深」= `hover:scale-[1.14]` + 文字 fading→ink + 浮纸面底，实测
  `transform: none → matrix(1.14,...)`、`color: #A39B8B → #2D2A24`。
- 四个字段 chip 排 2×2，刻度尺编辑当前选中的那个；未设置的字段读数是**预览**（前缀「设为」），
  不动刻度就不写库。越界值先收敛成 safe，**读数与高亮同源**（否则会出现「读数 23:59 高亮 0 分」）。
- 抽屉关闭时组件不卸载，所以打开时要**复位 activeField 到「开始」**（否则下次打开还在改上次的字段）。
- 顺带堵住负区间：「结束」拖到开始之前时两端互相顶走，不再产生 `09:00–08:00`。

### 五、保存按钮

## 第四轮：副标题放大 + 修「任务行上移/下移无效」+ 月年切换动效 + 关于栏精简

用户三句话里藏了一个真 bug：「添加任务之后，任务后面的向上键和向下键是什么？点了没有任何反应。」

### 修了什么
1. **`useTaskStore.move` 换位是无效的（真 bug）**。根因：`move()` 只把 `order` 换好了，
   而 `TasksPage` 按**数组位置**渲染 —— 数据其实写进库了，页面纹丝不动，
   **刷新一下反而「突然」换了位**。用户看到的正是「点了没反应」。
   修法：展示顺序改为 `tasks.filter(alive).sort(compareByOrder)` **从 `order` 派生**
   （与板块树 `buildTree` 同一套约定）。数组位置从此只是存放细节。
   顺带修掉第二个洞：`move` 原来在**全部**任务（含软删）里找相邻项 ——
   软删任务已经不在页面上，却会白占一次位移。现在只在存活任务之间换位，
   且不动软删任务的 `order`，于是「删除 → 撤销」天然回到原名次。
2. **`byOrderThenCreated` 从 `repositories/mappers` 迁到 `domain/constants` 并改名 `compareByOrder`**：
   store 需要它，而 store 反向 import 仓储层是分层倒挂。排序是业务规则，不是存储细节。
   4 个仓储改从 `@/domain/constants` 取（`export {…} from` 的别名转发没留 —— 两个名字就是漂移的种子）。
3. **任务行三个按钮**：加 `canMoveUp/canMoveDown`（首行上移、末行下移 `disabled:opacity-25`）、
   补 `.press` 按压反馈、补 `title`；上移/下移收进一个下沉底胶囊（它们是一件事），删除另起一格。
   原来三个按钮**既没有按压反馈、边界又是静默空操作**，看起来就是坏的。
4. **`PageHeader` 副标题 13 → 15px**（四屏共用的页头），日期入口箭头 11 → 13。
5. **日历 月 ⇄ 年**：段控加等宽滑块（`translateX(0|54px)`，280ms）；两个视图面板 `key={view}`
   + `m-zoom-out`（0.965→1，进年视图=拉远）/ `m-zoom-in`（1.04→1，进月视图=拉近），

30. **「点了没反应」要先去读渲染链路，而不是怀疑事件绑定**。这次 `onClick` → store 一条都没断，
    断在「store 改了 A 字段、渲染读的是 B 字段」。这类 bug 的指纹很好认：
    **刷新后状态是对的**。凡是「操作无效但刷新后生效」，一律去查
