### 已修：SectionPage 的 `?date=` 死参数（P0，静默写错日期）
`DiaryList` 跳转带 `?date=`，但 `SectionPage` 只读 `useDayStore`，URL 参数从不被读取。
HashRouter 下刷新 `#/section/work?date=X` 会让 store 回到今天，再点「+ 添加条目」
（`addSibling(..., date, key)`）**把条目写进今天**。

修法（eng-feature）：`src/pages/SectionPage.tsx` 用 `useSearchParams` 读 `date`，
**校验 `isValidDateKey` 合法后**单向 `setDate` 写回 store：
```tsx
useEffect(() => {
  if (!queryDate || !isValidDateKey(queryDate)) return; // 非法值直接忽略
  if (queryDate === useDayStore.getState().date) return;
  useDayStore.getState().setDate(queryDate);
}, [queryDate]);
```
- **无第二个并行日期变量**（全库 grep `effectiveDate|resolvedDate|bootstrapDate` 零命中）；
  副标题 / `useTreeEditor` / `addSibling` 一律只读 store 的 `date`。store 仍是唯一真相源。
- 复用 `src/utils/date.ts:60` 已有的 `isValidDateKey`（正则 + `parseDateKey`→`toDateKey` round-trip），
  未新建校验函数。`TodayPage` / `TimelinePage` 经 grep 确认无同类死参数。

### 独立验证（qa-nav，298 用例）
- N1（删掉 `isValidDateKey` 校验）：6 个非法值用例全红 ✅。
- N2（依赖改 `[]`）：**11 例全绿、零区分**。它另写一次性探针查明根因 —— react-router 在同一路由
  `/section/:sectionId` 内把 query 从 `date=A` 换成 `date=B` **不会 remount**（探针实测 mount 计数恒 1），
  此时 `[queryDate]` 会重新触发、`[]` 不会。但**本 App 无「板块页→板块页」入口**
  （SectionPage 唯一出口是 `onBack → navigate('/today')`），故真实路径上二者不可区分。
  **没有为它造假的 section→section 用例**（这点做得对）。结论：`[queryDate]` 保留，是防御性更好的选择；
  当前无测试能锁住差异 —— 记此处，未来若新增板块间直达链接，需要补这条覆盖。

## 增量 4：主页四板块组内联快速添加（R-039 / T31 / M8）

### 设计决策（我定的，两个关键取舍）
1. **不新增 store action，而是扩展 `addSibling` 增加可选第 4 参 `title?: string`**。
   依据：`treeService.createSiblingAfter(items, afterId, draft, clock)` 本来就消费 `draft.title`，

   还会瞬时产生一条空标题条目。用 `markItems` 命中次数 = 1 把它锁死。

4. 按钮激活态用**本板块 `color`/`tint`**（work #3B82F6/#EFF6FF、study #8B5CF6/#F5F3FF、
   fitness #F97316/#FFF7ED、life #10B981/#ECFDF5），与组头圆点一致。

### 画布操作踩坑（复用价值高）
1. **SVG 换色不能靠替换 `svg` 字符串**：SVG 一旦被解析成 VECTOR/RECTANGLE 子节点，
   `U(frameId, {svg: ...})` 会返回成功但渲染不变。必须 `batch_read` 拿到**底层矢量节点 id**，
   再改其 `fills` / `strokes`。B 版全部图标靠此修好；C 版从一开始就直改 fills/strokes。
2. **SVG 里不要写 `<g transform=...>`，也不要用弧线 path**：会报 `parsed to degenerate geometry`。
   五连心/星改成 5 个独立 14×14 `layout:"none"` 子 frame；wifi 弧线改成 3 个小矩形。
3. **Copy 的 `descendants` 参数不生效**（报 `Copy descendant not found`）。
   正确做法：Copy 后 `batch_read` 新节点拿新 id，再用独立 `U()` 逐条改。
4. Copy 出来的屏可能丢结构：C3 抽屉复制自 A3 但**缺「按钮行」**，靠 `capture_layout` + 对照 A3 子结构才发现，
   已手工 I() 重建（删除 / 完成两按钮）。
5. 当前模型**读不了 PNG**（Read 返回 content filtered），视觉核验只能靠
   `capture_layout(problemsOnly)` + `batch_read` 声明值交叉验证。

### 画布操作新踩坑
6. **实例（ref）内嵌孙节点不可覆盖**：`U("实例id;子id")` 两层可用，
   `U("实例id;子id;孙id")` 与 `U("实例id;子id/孙id")` 都报 not found。
   → 需要逐屏改 Tab 高亮时，**不要用 ref 实例**，改用 `C()` 复制导航条（后代拿到新 id 可直接 U），
   复制出的 id 规律是**连续分配**：base+1 胶囊、base+2..base+6 五个 Tab、
   base+17..base+26 各 Tab 的两个图标图元，读出前两个即可推出其余。
7. **空文本节点（`content:""`）即使用 `layoutGrow:1` 宽度也是 0**，会让整行栅格错位。
   修法：`U(id, {width:47, layoutGrow:0})` 显式给宽度。
8. 把节点转组件（`U(id,{reusable:true})`）会**换 id**（如 2:804→3:1），但子节点 id 保持不变。
