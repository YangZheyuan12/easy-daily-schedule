# 日程表 · 今日完成

移动端优先的日程与完成情况记录工具。**日记体统一列表**（工作 / 学习 / 健身 / 生活 / 灵感）+
树状拆解 + **时间轴（计划 + 记录）**，30 秒内记完今天做了什么、做得怎么样。

## 快速开始

```bash
npm install
npm run dev          # 开发，默认 http://localhost:5173，已开启 host 可用手机在同局域网访问
npm run verify       # 分层检查 + 类型检查 + 单测 + 生产构建
```

## 已实现的 P0 能力

| 能力 | 说明 |
| --- | --- |
| 今日首页 | 日期切换 + **日记体统一列表**：工作/学习/健身/生活/灵感五组**恒显**、顶层条目跨组连续编号 1~N、子项缩进跟随；四个板块组内**内联快速添加**（输入框 + 「添加」按钮，主页直接新增顶层条目、不跳转）；点组标题钻取进板块详情；日期栏在日期大字下方可显示**农历 / 二十四节气 / 节日**副标题（如「九月初三 · 中秋节」） |
| 自我状态 | 列表上方**紧凑横条**（♥×5 ★×5 + 文字摘要一行，点开展开编辑）；当日心情♥/身体★ 各 0–5 + 可选自由文字，落 `DailySelfStatus` 表，可反复修改 |
| 灵感 | 主页第 5 组纯文字条目：无勾选/评分/子项，组底快捷新增；计入当天「有无记录」但不参与四板块完成度、不影响日历四色点 |
| 板块详情 | 无限层级缩进树（主页点组标题钻取进入）：回车连续录入、Tab 降级、Shift+Tab 升级、折叠展开、完成态勾选 |
| 条目抽屉 | 任务描述（自动增高长文本）+ 个人评价（1–5 星 + 文字）+ 添加子分支 + 上/下移 |
| 删除撤销 | 递归软删整棵子树，5 秒内可完整恢复层级 / 顺序 / 折叠态 |
| 每日任务 | 增删改、勾选、排序，支持**一键继承昨日未完成**（幂等，连点不重复） |
| 时间轴 | 底部 Tab「时间轴」（`/timeline`，底栏顺序 今日/任务/时间轴/日历/我的）：**计划 + 记录一档两用**——可提前写未来计划，也可事后补实际开始/结束时间；含内容、可选板块标签、完成勾选；顶部日期可点击跳日历并落同一天；当天有「已到计划时段且未完成」时打开 App 顶部横幅提醒（可关闭） |
| 日历 | 月视图 / **年视图**切换：月视图四板块色点打点；年视图一屏 12 个月缩略网格，含数据月份显示四色小点 / 「N 天有记录」；某天摘要卡提供「当日 / 时间轴 / 任务」三跳转入口；选中日摘要卡显示**农历 / 节气 / 节日**行。**月历格子与年视图不显示节日**（格子高度与布局不变） |
| 本地持久化 | IndexedDB（Dexie），输入防抖 500ms + 离散操作立即写 + 切后台强制 flush |

## 未在 MVP 内（P1 / P2）

- P1：模板复用、真拖拽排序、统计回顾页（周/月趋势 + 热力日历）、数据导入导出、PWA、板块自定义、深色模式
- 「我的」优先级口径：底栏 Tab 入口为 **P0**（当前为占位页：版本信息 + 数据存放说明）；其完整功能（模板管理 / 数据导出导入 / 偏好设置）为 **P1**，账号同步为 **P2**
- P2：云端同步、图谱视图、提醒通知（系统通知/推送；**应用内提醒**已由 R-036 在 P0 实现）、标签系统、周报自动生成

## 架构要点

```
src/
  domain/        类型 + 常量 + 仓储接口 + 错误（零依赖）
  repositories/  Dexie 实现，唯一允许触碰存储 API 的目录
  services/      树算法 / 完成度 / 继承 / 撤销 / 持久化调度 / 农历·节气·节日（纯 TS、零依赖）
  store/         Zustand + 依赖装配
  components/    UI 组件
  pages/         五个 Tab 页面
  utils/ hooks/  日期、防抖、键盘交互等
```

**分层红线**（由 `npm run check:layers` 强制）：`domain/` 与 `services/`
禁止出现 `window` / `document` / `localStorage` / `indexedDB` 等浏览器 API，
UI 层禁止直接 import `repositories`。这是迁移到微信小程序时业务内核能
100% 复用的前提 —— 届时只需替换 `src/repositories/` 的实现。

关键设计决策见 `docs/ARCHITECTURE.md`，任务分解见 `docs/TASKS.md`，需求见 `docs/PRD.md`。

## 完成度口径

- 板块完成率 = **顶层条目**完成数 ÷ 顶层条目总数（子项不重复计入分母）；四板块卡片已由日记体统一列表取代，该口径仍用于板块详情页（钻取视图）
- 原「完成度百分比进度环 / 环形图中心总完成率」已由 R-030 的**自我状态双评分（mood♥ / body★）**取代，不再展示加权完成率环
- 灵感条目**不参与**四板块完成度统计，但计入当天「有无记录」（hasData）
- 勾选父条目**不联动**子项：父只展示直系 `子项完成/子项总数`

## MVP 验收路径

1. 打开应用 → 今日首页，看到顶部**自我状态紧凑横条**与**日记体统一列表**（工作/学习/健身/生活/灵感五组恒显、顶层跨组连续编号 1~N）
2. 切到「任务」Tab → 添加两条今日任务 → 勾选一条 → 进度条更新
3. 回到首页 → 点「工作:」组标题进入工作板块详情页（钻取视图）
4. 输入一条完成情况 → 回车连续录入第二条 → Tab 把它缩进成子分支 → Shift+Tab 升回来
5. 点右侧 `⋯` 打开抽屉 → 写任务描述 → 打 4 星 → 写一句评价 → 关闭
6. 勾选完成 → 返回首页，统一列表完成态与编号同步更新
7. 删除一条含子分支的条目 → 底部出现撤销条 → 点撤销，层级与折叠态完整恢复
8. **刷新页面** → 数据 100% 保留
9. 首页顶部自我状态横条 → 点开 → 给 mood 3 颗♥、写「今天挨训了，不开心」；给 body 5 颗★、写「健身满分」→ 收起后横条显示摘要
10. 灵感组底部「＋」→ 快捷新增一条纯文字点子 → 该条无勾选/评分/子项，出现在灵感组
11. 灵感口径验证：灵感条目不改变四板块完成度、不改变日历四色点，但计入当天「有记录」
12. 内联快速添加验证：在「健身:」组内联输入框输入「跑步 30 分钟」→ 点「添加」（或回车）→ 条目立即出现在健身组末尾并纳入顶层连续编号，输入框清空且保持聚焦；输入为空时「添加」按钮禁用；把「健身」清空后组头仍显示（五组恒显），顶层编号不因空组中断
13. 切到「时间轴」Tab → 给明天新增一条计划「09:00–10:00 晨跑」、选「健身」标签（计划态）→ 保存
14. 回今天 → 若存在「已到计划时段且未完成」的时间块，打开 App 顶部显示提醒横幅 → 点关闭消失
15. 时间轴页把某条标记实际完成 → 补实际开始/结束时间（如 13:05–14:50）→ 计划/实际两态并显
16. 点时间轴顶部日期 → 跳转日历页并选中该天；切到年视图，一屏 12 个月缩略网格，含数据月份显示四色小点 /「N 天有记录」
17. 点某月进入月视图（有记录日子四色点点亮，今天蓝框高亮）→ 点某天看摘要卡 → 点「当日 / 时间轴 / 任务」任一入口 → 先切日期再跳对应页面
18. 农历 / 节日验证：回今日页 → 日期大字下方出现「九月初三 · 中秋节」之类一行 → 进日历页点同一天 → 摘要卡标题行下方显示同一行 → 随便点一个没有节日的日子 → 该行只显示农历日期（如「八月十六」）→ 打开月视图逐格检查，确认**日历格子里没有任何节日文字、格子高度与布局没变**（年视图同样不显示节日）

## 技术栈

Vite 5 · React 18 · TypeScript · Tailwind CSS 3 · Zustand 4 · Dexie 4 · React Router 6

> 说明：原架构方案中的 MUI v5 已移除，改为 Tailwind + 手写移动端组件。
> 原因：MUI 与 Tailwind 共存需处理 preflight 冲突，包体增加约 300KB，
> 且在迁移小程序时 MUI 组件全部不可用、重写成本反而更高。

> 农历算法为内置压缩表（覆盖 1900–2100），二十四节气为实时求解太阳视黄经（Meeus 低精度算法 + 牛顿迭代，按北京时间定日）；未引入 lunar-javascript / solarlunar 等第三方依赖，也不发起任何网络请求（离线可用）。

## 打包成手机 App（Capacitor）

本项目本体是网页，但已经套好了 Capacitor 原生壳，`android/` 与 `ios/` 两个原生工程**已入库**。

```bash
npm run mobile:sync      # vite build + cap sync（两端都同步）
npm run mobile:android   # 同步并打开 Android Studio
npm run mobile:ios       # 同步并打开 Xcode
```

不想碰原生工具链的话，网页版就够用：`pages.yml` 会把产物部署到 GitHub Pages
（需要先在仓库 Settings → Pages → Source 选 **GitHub Actions**，只设一次），
iPhone 上用 Safari 打开 →「添加到主屏幕」，就有 App 图标，离线可用。

> **下载 APK 时容易点错**：一次推送会同时触发 **CI / Mobile / Pages 三个独立运行**。
> 只有 **Mobile** 那次运行底部的 Artifacts 里才有 `android-debug-apk`；
> CI 那次的产物叫 `web-dist`（网页构建产物），不是安装包。

⚠️ 两条硬约束：

- **iOS 必须有 Mac，没有第三条路。** Apple 不允许未签名 App 装进 iPhone，签名要么靠
  **装了 Xcode 的 Mac**（免费 Apple ID 自签，7 天有效期，到期重签），要么靠
  **Apple Developer 账号**（99 美元/年，配好证书后 CI 才能自动签名）。
  Windows 上只能准备工程、跑 `cap sync`，**产不出能装的东西**。
  CI 里那个 iOS job 的定位因此改成**编译校验**（编模拟器版，模拟器不需要签名），
  它的产物 `ios-simulator-app` 同样**装不到真机**。
  → 手上没 Mac 又想在 iPhone 上用：**用 Pages 网页版，Safari「添加到主屏幕」**。
- **Android 出的是 debug APK**，可以直接装，不需要任何账号。

完整评估（四条路线对比、逐项改动清单、待办）见 `docs/MOBILE-APP-MIGRATION.md`。

## 注意事项

**跑单测时若发现用例总数对不上，先怀疑执行环境，不要怀疑代码。**

在某些受限执行环境（沙箱 / 只读临时目录）里，Vite 的 SSR 依赖优化缓存需要写
`%TEMP%`，会被拦截并报 `EPERM: operation not permitted`，结果是**整包
`vitest run` 会静默丢掉某一个测试文件**。这是执行环境限制，**不是项目缺陷**。

最坑的一点是：丢文件时 **vitest 退出码仍然是 0、控制台整体依旧显绿** ——
也就是说「显绿」不等于「全跑到了」，只看整体颜色会漏掉真实失败。

**新增 / 怀疑漏跑时，用严格验收脚本一键校验：**

```bash
npm run test:strict
```

它会遍历 `src/` 下所有 `*.test.ts`，**逐个文件**单独 spawn vitest，然后汇总
输出「文件名 / 用例数 / 是否通过」。只要有任何文件没被收集到或执行失败，
就 **exit 1** 并明确打印是哪个文件丢了 —— 防的就是「静默丢文件」这件事。
脚本刻意**不**硬校验总数必须等于某个常量，避免每加一个用例就要改一次配置。

参考基线：本仓库的单测用例总数随增量持续增长，**请以 `npm run test:strict` 的
实际输出为准，不要以本文档中的任何硬编码数字为准**（逐文件枚举清单已移除——
它每新增一个测试文件就会过期，维护成本永远大于收益）。冻结快照口径：文件数 /
用例数请现场采集，不在文档里固化。

在正常环境（可写临时目录的普通开发机）里，整包 `npm test` 通常也是
**全部测试文件全绿、零丢弃**，那才是日常快路径；但「显绿」不等于「全跑到了」，
`test:strict` 才是严格验收或怀疑丢文件时的准绳。

> 补充：`tsc --noEmit` 也要单独跑。某些类型错误（例如同一个模块重复 import）
> 在运行时是无害的（测试照过），只有类型检查能拦住。
